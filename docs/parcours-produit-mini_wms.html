De l'achat à l'expédition, chaque étape produit UN mouvement — et rien d'autre. Le sens vient des emplacements (dont les virtuels), jamais d'un signe ni d'un type. Le stock n'est stocké nulle part : il se calcule, à tout instant, comme la somme du journal.

→ mouvement DONE (réel) - - → mouvement DRAFT (intention) OR = emplacement VIRTUEL blanc = emplacement physique bleu = document métier
UNE mécaniqueAchat, rangement, production, casse, expédition : huit situations métier, un seul concept. Pas de type ENTRÉE/SORTIE en dur, pas de quantité négative — le sens vient des emplacements. Ajouter un cas métier (retour client, inventaire, transfert inter-sites) ne demande aucun code nouveau : juste un couple source → destination.
VirtuelsFOURNISSEUR, CLIENT, PRODUCTION, PERTE, INVENTAIRE sont des emplacements comme les autres — ils n'existent juste pas physiquement. C'est l'astuce qui rend le modèle uniforme : tout mouvement a toujours une source ET une destination, donc le journal est équilibré, façon comptabilité en partie double.
① vs ②La commande planifie, la réception exécute. Un document n'est pas un fait : seule la validation de la réception génère le mouvement. Le reliquat (commandé − reçu) n'est pas une colonne à maintenir, c'est une soustraction. Une réception sans commande reste possible (FK nullable).
④ le DRAFTL'allocation est un mouvement non validé : il n'entre pas dans le physique, mais il ampute le disponible. C'est ainsi qu'on évite de promettre deux fois la même palette — sans jamais inventer de table « réservation ». Quand le camion part, le même mouvement passe simplement en DONE.
ImmuableUn mouvement DONE ne se modifie ni ne se supprime jamais. Erreur de saisie → on écrit un mouvement inverse. Le journal reste un historique auditable : on voit l'erreur ET sa correction. C'est aussi pourquoi Mouvement est la seule table où les champs personnalisés sont interdits (§6octies).
Performance« Recalculer à chaque fois, ce n'est pas lent ? » — non, à l'échelle d'une PME. Le jour où ça se voit (centaines de milliers de mouvements), la réponse est une table de snapshot (stock figé à une date de clôture) + le delta depuis. Pas avant que la lenteur soit mesurée.
